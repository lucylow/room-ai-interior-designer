# Retail Monetization V6 integration

V6 is kept behind `server/retail-monetization-v6`, preserving the complete cart, pricing, fulfillment, checkout, order, webhook, referral, affiliate, and revenue modules without placing live-provider adapters in the React client bundle. The client-facing `src/state/domains/retail-commerce-v6-store.ts` stores cart snapshots only. Cart lines retain project, room, concept, and placement provenance; distinct concept placements of the same variant remain distinct lines. Budget caps are enforced before cart mutation and again by checkout validation.

Provider requests have deadlines and normalize network, timeout, HTTP, and malformed-response failures. Checkout operations coalesce concurrent retries by scoped idempotency key, clone caller-visible session objects, bind sessions to a cart version, and cancel/reject a session if the cart changes during provider creation. Failed provider-session cancellation is surfaced as a reconciliation-required error. Cart validation rejects invalid prices, currencies, quantities, inventory and commission rates before provider calls. Checkout API handlers return stable error codes rather than raw provider bodies or secrets.

Live Stripe/Shopify checkout is not configured or invoked by this integration. No provider credentials were supplied. The deterministic demo provider is the only provider exercised by tests. Provider-specific Stripe timestamped HMAC and Shopify HMAC verification are implemented under `server/webhooks`; the deterministic demo-signature helper is not used to accept live webhook events. The in-memory cart, checkout idempotency, and webhook stores still need durable transactional storage and provider-specific amount/order reconciliation before production deployment. Keep all secrets server-only. Never mark an order paid from a client callback; the order service requires a stored, verified, provider-matching payment event.

Synthetic catalog, purchase journeys, and demo payment scenarios are fixtures only. Run `pnpm run commerce-v6:check` for strict typechecking, focused tests, and commerce-specific ESLint.
